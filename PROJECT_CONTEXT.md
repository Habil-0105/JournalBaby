## 1. Project Summary

**MiroCloneiPad** is a SwiftUI / UIKit iPad-and-iPhone journaling / whiteboard app that renders a multi-page board of text, image, audio, and freehand-drawing "blocks" presented as a flip-through book of pages using `UIPageViewController`'s native `.pageCurl` transition. Despite its name ("iPad"), the current build is single-page mode on every device — the previous two-page iPad spread mode was removed in `b87737e remove 2 page`.

The app stores all blocks in memory in a single `CanvasStore` (no persistence: SwiftData was removed in `ab4a337 feat: push`); images and audio clips are written to `Documents/Images/` and `Documents/Audio/` as plain files.

## 2. Project Goals

Verified from code comments, commit messages, and `.DS_Store`-free clean-room inspection:

- Multi-block "whiteboard / journal" pages with several media kinds (text, image, audio, drawing).
- Automatic flow layout — blocks are laid out left-to-right, top-to-bottom, wrapping into rows and overflowing into new pages automatically. Verified by the comment on `CanvasElement` and the layout engine in `CanvasStore.layoutPages`.
- "Tap to select, then interact" affordance — gestures are partitioned so resize handles do not fight with text/drawing touch input. Verified in `ElementContainerView` and `DrawingElementView` comments.
- Page turning via realistic `.pageCurl` animation. Verified by `BookPageCurlView` usage of `UIPageViewController(transitionStyle: .pageCurl)`.
- Drawings can be resized without distorting the strokes (locked aspect-ratio corner scale handle that transforms `PKDrawing` strokes in lockstep with the frame). Verified in `ElementContainerView.cornerScaleGesture` and `CanvasStore.scaleDrawing`.

## 3. Architecture

Three layers:

1. **Models** (`MiroCloneiPad/Models/`)
   - `CanvasElement.swift` — Pure value type + enum `ElementKind` + layout output structs (`PlacedElement`, `PageLayout`, `BookSpread`).
   - `CanvasStore.swift` — `ObservableObject` that owns all blocks and runs the layout engine. The single source of truth for blocks (`elements`), drawing strokes (`drawings`), measured text heights (`textHeights`), drawing content size tracking (`drawingContentSizes`), `containerWidth`, `selectedElementID`, and `currentPageIndex`.
   - `TextSplitter.swift` — CoreText utility that measures wrapped text height and finds how many characters fit in a width × max-height rectangle.

2. **Canvas / page rendering** (`MiroCloneiPad/Canvas/`)
   - `BookPageCurlView.swift` — `UIViewControllerRepresentable` wrapping a `UIPageViewController(transitionStyle: .pageCurl)`. The Coordinator is the data source + delegate and records the current spread index back into `store.currentPageIndex`.
   - `BookSpreadView.swift` — Renders a single physical spread. In single-page mode (current build) this just renders its `leftPage` via `PageView`. `SpineGutterView` is defined but unused since `remove 2 page` landed.
   - `PageView.swift` — Renders a single page: header "Page N of M", a `ZStack` of placed elements, rounded-rect card, shadow, and a decorative dog-ear corner.
   - `ElementContainerView.swift` — Wraps an element at the frame `layoutPages` gave it. Tap-to-select, delete button, width handle, height handle, corner scale handle (drawings only).
   - `ScribbleCanvasView.swift` — `PKCanvasView` wrapper that only accepts input when its block is selected.

3. **Element views** (`MiroCloneiPad/Elements/`)
   - One file per block kind: `TextElementView`, `ImageElementView`, `AudioElementView`, `AudioRecorderSheet` (modal), `DrawingElementView`, `AutoGrowingTextView` (`UITextView` wrapper).

Data flow:

```
ContentView (NavigationStack + GeometryReader)
  → CanvasStore.layoutPages / layoutSpreads  (computes pages from blocks each render)
  → BookPageCurlView (UIPageViewController)
      → BookSpreadView  (one per spread)
          → PageView    (rounds + header + ZStack of placed slices)
              → ElementContainerView  (handles, delete, gestures)
                  → TextElementView / ImageElementView / AudioElementView / DrawingElementView
                  → AutoGrowingTextView / ScribbleCanvasView (UIKit bridges)
  mutations funnel back into CanvasStore (selectedElementID, setWidth, setHeight, scaleDrawing, addX, remove, updateTextSlice)
```

## 6. Main Application Flows

### Add a block
1. User taps toolbar button in `ContentView`.
2. `ContentView` calls `store.addX()` (e.g. `addText()`, `addImage(data:)`, `addAudio(fileURL:duration:)`, `addDrawing()`).
3. Each `addX` appends to `elements`, sets `selectedElementID`, initializes any auxiliary storage (`drawings[id]`, `drawingContentSizes[id]`), and calls `focusLastPage()` which sets `currentPageIndex` to the last page.
4. The page-curl controller animates to the new page.

### Add image specifically
1. `PhotosPicker(selection: $photosPickerItem)` → on change, `PhotosPickerItem.loadTransferable(type: Data.self)` returns a `Data`.
2. `store.addImage(data:)` writes it to `Documents/Images/<uuid>.jpg` and creates an element.

### Record audio
1. Toolbar mic button sets `showAudioSheet = true`.
2. `AudioRecorderSheet` runs; `AudioRecorderManager.requestPermissionAndStart()` requests `AVAudioSession.sharedInstance().requestRecordPermission`, records to `temporaryDirectory/<uuid>.m4a`, tracks elapsed time with `Timer`.
3. On stop, `store.addAudio(fileURL:duration:)` copies the temp file into `Documents/Audio/<uuid>.m4a` and creates an element.
4. Playback: `AudioElementView` uses an `AudioPlaybackManager` (per-view `StateObject`) that owns an `AVAudioPlayer` and toggles play/stop.

### Edit text
1. Tap block to select. `selectedElementID = id`. `ElementContainerView` shows handles and re-renders content with `isSelected = true`.
2. `TextElementView` → `AutoGrowingTextView(isEditable: isSelected)` only accepts input when selected.
3. On text change, `AutoGrowingTextView` reports new height to `store.setTextHeight`, which is stored in `textHeights[id]`. (Note: `textHeights` is set but the layout engine uses `TextSplitter.measureHeight` instead — see "Known technical debt".)
4. The text binding joins slices back into a single `element.text` via `store.updateTextSlice(canonicalID:sliceIndex:newText:slices:)`.

### Resize block
- Text: no user height handle; height is automatic.
- Image/Audio: independent width + height edge handles.
- Drawing: ONE corner handle that locks aspect ratio. Drag → `cornerScaleGesture` reads back the post-clamp `setWidth` / `setHeight` results, then calls `store.scaleDrawing(_, to:)` which transforms the stored `PKDrawing` strokes by the same scale factor. This is the only way drawing strokes get rescaled.

### Page navigation
- `UIPageViewController(transitionStyle: .pageCurl)` + `Coordinator` as `UIPageViewControllerDataSource` and `UIPageViewControllerDelegate`.
- Paging uses `store.currentPageIndex` as the canonical state. `Coordinator.didFinishAnimating` writes back the visible page's index after a swipe completes.

## 7. Data Model

### `ElementKind` (enum, `Codable`)
`.text`, `.image`, `.audio`, `.drawing` — the four supported block kinds.

### `CanvasElement` (`Identifiable, Codable, Equatable`)
```
id: UUID
kind: ElementKind
width: CGFloat                    // user-resizable, clamped at layout time
height: CGFloat                   // ignored for .text
text: String?                     // .text only
imageFileName: String?            // .image only (in Documents/Images)
audioFileName: String?            // .audio only (in Documents/Audio)
audioDuration: TimeInterval?      // .audio only
```

The struct intentionally has no `(x, y)` — the comment on the struct is explicit that position is always *derived* by the layout engine.

### `PlacedElement` (Identifiable, Equatable)
Output of the layout engine. `id` is "\(uuid)_slice_\(i)". Carries `canonicalID`, `frame: CGRect`, optional `textSubstring`, `isSplitText`, `sliceIndex`.

### `PageLayout` (Identifiable, Equatable)
`id: Int`, `pageIndex: Int`, `elements: [PlacedElement]`.

### `BookSpread` (Identifiable, Equatable)
`spreadIndex: Int`, optional `leftPage`, optional `rightPage`. In single-page mode, every `BookSpread` has `leftPage = page`, `rightPage = nil`.

### `CanvasStore` runtime state
- `@Published elements: [CanvasElement]` — owned blocks.
- `@Published drawings: [UUID: PKDrawing]` — PencilKit strokes keyed by element id.
- `@Published selectedElementID: UUID?`
- `@Published textHeights: [UUID: CGFloat]` — measured heights fed back from `AutoGrowingTextView`.
- `@Published drawingContentSizes: [UUID: CGSize]` — the frame each drawing's strokes are currently expressed in.
- `@Published private(set) containerWidth: CGFloat` — derived from `GeometryReader` in `ContentView`.
- `@Published currentPageIndex: Int`
- Disk-backed: `Documents/Images/*.jpg`, `Documents/Audio/*.m4a`.

## 8. Important Components

- `CanvasStore.layoutPages(pageWidth:pageHeight:)` (`CanvasStore.swift:67`) — the heart of the app. A row-wrap flow layout that, for each block, either fits it in the current row or wraps; for text, calls `TextSplitter.fittingLength` then `measureHeight` to slice at line boundaries and finish pages when content overflows. Returns `[PageLayout]`.
- `CanvasStore.layoutSpreads(pageWidth:pageHeight:)` (`CanvasStore.swift:225`) — maps pages 1-to-1 to spreads in single-page mode (the iPad 2-page logic was deleted in `b87737e`).
- `TextSplitter` (`TextSplitter.swift`) — uses `CTFramesetterCreateWithAttributedString` and `CTFrameGetVisibleStringRange` for accurate wrapping + per-page character counts.
- `BookPageCurlView.Coordinator` (`BookPageCurlView.swift:39`) — bridges UIPageViewController ↔ SwiftUI by hosting `BookSpreadView` in `PageHostingController`.
- `ElementContainerView` — sole place the resize / select / delete gestures live. Holds `@State widthDelta / heightDelta` for live preview; commits via `store.setWidth` / `setHeight` on `.onEnded`.
- `AutoGrowingTextView` — `UIViewRepresentable` over `UITextView` with `widthTracksTextView = true`, `isScrollEnabled = false`, custom `sizeThatFits(_:uiView:context:)` that pins wrap width.
- `ScribbleCanvasView` — `UIViewRepresentable` over `PKCanvasView`. Allows both finger + Apple Pencil (`drawingPolicy = .anyInput`).
- `DesignSystem` — single source of spacing/sizing constants (`pagePadding`, `blockSpacing`, `blockContentPadding`, `cornerRadius`, `minBlockWidth=160`, `minBlockHeight=90`, `pageHeaderHeight=36`, `spineGutterWidth=24`).

## 16. Project Conventions

- **`final class` for `ObservableObject`s** (`CanvasStore`, `AudioRecorderManager`, `AudioPlaybackManager`).

- **Constant-first layouts**: layout always derives positions from block order + size, never stores `(x, y)` — preserves the "resize one block reflows everything" property by construction.

- **`UIViewRepresentable` wrappers always implement `makeCoordinator`** for delegate plumbing.
- **SwiftUI body never relies on intrinsic text-view width** — every text-bearing view that has to wrap inside a fixed width sets `.frame(width:)` or overrides `sizeThatFits`.

## 18. Known Technical Debt

1. **No persistence of blocks.** `CanvasStore.elements` is purely in-memory. SwiftData and `Item` / `MiroCloneiPadApp.swift` were removed in `ab4a337`; no replacement was added. Images/audio survive as files, but their owning blocks and their `textHeights` / `drawingContentSizes` / `drawings` are lost on relaunch.
2. **`textHeights` is dead state.** It is written by `AutoGrowingTextView` via `store.setTextHeight`, but `CanvasStore.layoutPages` for `.text` blocks calls `TextSplitter.measureHeight(...)` directly instead of using `textHeights[id]`. The two can disagree — UIKit's `sizeThatFits` vs. CoreText's framesetter.
3. **Stray `print` debugging**: `ContentView.swift:29,31` print `"111"` / `"222"` in the page-count `onChange` handler — appears to be a diagnostic left behind; should be removed.
4. **Debug `print`s in store / audio**: `CanvasStore.swift:274, 294` and `AudioElementView.swift:61`, `AudioRecorderSheet.swift:52` print errors to stdout. Not surfaced in UI.
5. **Dead code: `SpineGutterView` and `DesignSystem.spineGutterWidth`** — defined and unused since `b87737e` removed two-page spread mode.
6. **No `.gitignore` for `DerivedData/`.** Build artifacts are tracked in git history (see commits `56898c9 push` and `99ff378 feat: allow pages` which include `DerivedData/Build/...` and `ModuleCache.noindex/...` files). Multiple commits only changed build outputs.
7. **No unit / UI tests.**
8. **`focusLastPage()` uses a stub `pageHeight: 800`** (`CanvasStore.swift:320`) when deciding where to land the cursor after adding a block. Unrelated to visible geometry; can mis-target pages on small screens.
9. **`ContentView.swift:13`** declares `singlePageWidth = geo.size.width` but only uses it as the `pageWidth` argument to `layoutPages`. The `pages` array is computed but only its `.count` is consumed (line 16 / 26); the per-element page frames are recomputed inside `BookPageCurlView` via `parent.spreads`. Double layout per render.
10. **Layout is recomputed on every SwiftUI invalidation** because there is no memoization. With many blocks this will be `O(blocks²)` in worst case (text splitting plus full re-layout of every page). Adequate for small boards.
11. **`ContentView.swift` `onChange(of: pages.count)` only handles one edge case** (clamp `currentPageIndex`). When blocks are added/removed there is no general strategy for keeping the visible page in sync.

## 23. AI Mental Model

The system is a single-layer, single-window iOS app whose **only stateful service** is `CanvasStore`. There is no networking, no persistence layer, no auth, no analytics, no background work. Everything visible on screen is computed on demand from `CanvasStore` + a `GeometryReader` size.

There are three layers in practice:

1. **Pure data + layout engine** (`Models/`). `CanvasElement` is a value type; `CanvasStore` owns the array plus parallel side-tables (`drawings`, `textHeights`, `drawingContentSizes`) and runs `layoutPages`. Layout is recomputed each SwiftUI pass — cheap enough for small boards.
2. **Page-curl navigation** (`Canvas/BookPageCurlView`, `Canvas/BookSpreadView`, `Canvas/PageView`). Wraps UIKit's `UIPageViewController` and pages through `BookSpread`s. Current build is single page per spread.
3. **Block visualization + interaction** (`Canvas/ElementContainerView`, `Elements/*`). One renderer per kind, all uniform: tap to select, then interact.

The **main flows** are: user taps a toolbar button → `store.addX` appends a block + jumps to the last page; user taps a block → it becomes selected (handles appear, drawing canvas becomes active, text view becomes editable); user drags a handle → `ElementContainerView` shows a live preview from `@State widthDelta/heightDelta`, then on `.onEnded` commits to `CanvasStore.setWidth` / `setHeight` (and for drawings, also calls `scaleDrawing` to transform the `PKDrawing` strokes).

The **most important business logic** lives in:

- `CanvasStore.layoutPages` — the layout engine. Understand its invariants (text always on its own row, non-text wraps, overflow triggers a new page) before touching it.
- `TextSplitter` — CoreText-backed measurement; it is the source of truth for "how many characters fit" and "how tall is this text".
- `ElementContainerView.cornerScaleGesture` — the only place drawing strokes get retransformed; sequencing here matters because it reads back the post-clamp width / height from `setWidth` / `setHeight`.

When modifying:

- **Never reintroduce stored `(x, y)` on `CanvasElement`.** The whole "reflow on resize" property depends on derived positions.
- **If you add a new block kind**, you must extend `ElementKind`, `CanvasStore.addX`, `CanvasStore.layoutPages`, `ElementContainerView.content`, and probably add a new `Elements/XxxView.swift`.
- **If you change the page physics** (`UIPageViewController` spine location, transition style, two-page mode restoration), confirm `BookSpreadView` still knows how to render the resulting spreads.
- **Touching CoreText** is usually wrong — prefer `AutoGrowingTextView`'s `sizeThatFits` for height, and only use `TextSplitter` for the page-overflow character-splitting decision.
- **The big architectural constraint** is: *the model is the layout*. SwiftUI views re-derive from `CanvasStore`, never cache positions of their own. A change that caches positions in `@State` will break the next reflow.
